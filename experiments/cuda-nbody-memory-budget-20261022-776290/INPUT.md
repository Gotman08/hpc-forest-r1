# Entrée réellement fournie — campagne 776290

Les modèles reçoivent le code original et un contrat d'exécution : interface, matériel, corrections attendues et métrique. L'adaptateur N-body a été préparé pour cet exemple ; ce test ne prouve pas encore une ingestion de n'importe quel programme sans protocole préalable.

Aucun ancien noyau optimisé, ancien score ou conseil prescrivant une optimisation gagnante n'a été fourni. Le texte du problème et les skills génériques sont identiques aux deux relances précédentes. Mother choisit N, les sujets et les transformations. Les mesures et les corrections de candidats proviennent du contrôleur, sans intervention humaine pendant la campagne.

Les deux messages initiaux enregistrés totalisent **18098 caractères**, dont le code, le contrat, le schéma de réponse et les consignes génériques. Le contrat ajouté au code original représente **2816 caractères**. Quatre skills sont chargés pour la préparation : planification, inspection de l'environnement, consultation de documentation et évaluation des performances. Ce n'est pas une entrée minimale.

La borne de **12 000 caractères** concerne le paquet de mémoire récupéré. Elle ne borne pas tout le prompt ni l'historique natif ; la compaction de conversation est gérée par Codex CLI. Les chiffres ci-dessus excluent aussi l'habillage natif et les schémas des outils.

Les appels de Mother, des arbres et de la fusion se déroulent dans le budget de campagne. La préparation manuelle du protocole, la file d'attente et l'amorçage précédant le démarrage du contrôleur ne sont pas inclus dans les 30 minutes. Toute aide supplémentaire destinée à améliorer le système doit devenir une procédure générique et automatique, avec son coût visible, plutôt qu'une indication manuelle propre à N-body.
